# selfplay

Self-play RL engine for Gen 9 Champions VGC. The battle engine is Rust, with
Python bindings via PyO3. Plan and status are in [DESIGN.md](DESIGN.md).

## Layout

- `engine/`: pure-Rust battle engine (crate `selfplay-engine`, lib `engine`).
- `pybind/`: PyO3 bindings, built into the Python module `selfplay._engine`.
- `python/selfplay/`: the Python package.
- `data/dex.json`: species, moves, items, abilities, natures and type chart,
  exported from Showdown's Champions mod by `tools/showdown/export_dex.js`
  and embedded in the engine at compile time.
- `engine/tests/fixtures/`: expected results computed by Showdown's own code
  (`tools/showdown/gen_fixtures.js`). The engine's tests compare against them.
- `data/corpus/`: the team corpus (Showdown pastes; placement in the name
  sets how often a team is played).
- `data/regmc_pool.json`: the Reg M-C legal pool and usage, generated by
  `tools/gen_pool.py` from the Smogon stats in `data/smogon_stats/`.
- `tests/`: Python tests.

## Build

Needs Rust (https://rustup.rs) and, on Windows, the Visual Studio Build
Tools with "Desktop development with C++". `maturin develop` needs a
virtual environment. On Windows (PowerShell):

    cd selfplay
    py -3.11 -m venv .venv
    .venv\Scripts\Activate.ps1       # if blocked: Set-ExecutionPolicy -Scope CurrentUser RemoteSigned
    python -m pip install --upgrade pip
    pip install torch --index-url https://download.pytorch.org/whl/cu126   # CUDA build; see pytorch.org
    pip install maturin numpy pytest websockets
    maturin develop --release
    python -c "import torch, selfplay._engine; print(torch.cuda.is_available())"   # expect True

On Linux or macOS: `python -m venv .venv && source .venv/bin/activate`, then
the same. Activate the venv in every new terminal. Without a venv,
`pip install ./selfplay` also works (rebuild after engine changes).

## Test

    cd selfplay && cargo test        # unit tests plus the Showdown fixtures; no Node or Python needed
    cd selfplay && pytest tests      # the Python environment (after building the module)

## Self-play environment

    from selfplay.env import SelfPlayEnv
    env = SelfPlayEnv(1024)          # teams from data/corpus, weighted by placement; 30-turn cap
    obs = env.observe()              # numpy arrays for both sides, plus legal-action masks
    result = env.step(env.random_actions(seed=0))

    python -m selfplay.rollout --games 1000000    # random-play throughput (phase 2 exit test)
    cargo run --release --example bench           # engine speed, one core

See DESIGN.md 4.11 for the action and observation layouts.

## Training (needs PyTorch)

    python -m selfplay.train --imitate-minutes 3 --minutes 60 --minibatch 1024 --epochs 4 \
        --league-frac 0.5 --greedy-frac 0.5 --out runs/tiny     # add --device cuda on a GPU
    python -m selfplay.evaluate runs/tiny/model.pt --games 2000
    python -m selfplay.summary runs/tiny        # the run's log in a screenful

See DESIGN.md 4.13 for the model, the training setup and first results.

## Search

    python -m selfplay.search runs/tiny/model.pt --games 400 --k 8   # one-turn search vs the raw policy
    python -m selfplay.search_train --init runs/tiny/model.pt --minutes 600 --envs 256 \
        --device cuda --out runs/search                                  # search-labelled self-play
    python -m selfplay.evaluate runs/search/model.pt --against runs/tiny/model.pt

Each turn is solved as a matrix game between both sides' top-k joint
actions, every cell scored over its chance outcomes by the value network
(DESIGN.md 4.14).

The tree search (DESIGN.md 4.16) looks further: every node is such a matrix
game, grown where it matters, guided by the policy at every node:

    python -m selfplay.search MODEL --tree --tree-budget 2000 --vs-search --games 1000 --device cuda
    python -m selfplay.search MODEL --tree --tree-budget 2000 --vs-search --opp-tree --opp-tree-budget 500
    python -m selfplay.search MODEL --tree --tree-budget 2000 --tree-root-oracle --vs-search --opp-tree --opp-tree-budget 2000
    python -m selfplay.search_train --init MODEL --tree --tree-budget 800 --fast-budget 100 \
        --full-frac 0.25 --root-noise 0.25 --epochs 8 --envs 256 --device cuda --out runs/tree

Two models head to head, both searching (side 1 plays `--opp-model`):

    python -m selfplay.search runs/tree/model.pt --opp-model runs/big/model.pt --tree --vs-search --opp-tree --device cuda

## Teams

Training plays the tournament teams in `data/corpus` (weighted by
placement in the file name) plus your teams in `../data/teams` and
`../data/my_teams` (weight 4, as a top-8 team). Teams from those folders
are named "teams/<file>" and "my_teams/<file>". Teams that aren't legal or
use something the engine doesn't support are left out;
`SelfPlayEnv(1).rejected()` lists them with the reason.

## Play against the bot

    python -m selfplay.play runs/search/model.pt --you "my_teams/pseudo" --bot "teams/sand"
    python -m selfplay.play runs/search/model.pt --list          # team names

Teams are chosen by name or a unique part of it (random if left out). Each
turn, pick each Pokemon's action from the list; `h` shows the search's mix
for your side and its win estimate. The bot plays the one-turn search
(`--bot-plays double-oracle` or `policy` to change it).

## Teams against the meta

    python -m selfplay.meta runs/search/model.pt --teams my_teams teams/ --games 20 --csv meta.csv

Plays each team against every placed tournament team (Champion to Top 32),
on both sides, with the bot playing both, and ranks the teams by win rate
(plain and weighted by the opponents' placement), with their worst
matchups. The CSV has every matchup.

## Team ratings

    python -m selfplay.teams runs/ppo3/model.pt --device cuda --csv teams.csv
    python -m selfplay.teams runs/ppo3/model.pt --teams my_teams teams/ --top 4

Every team in the training corpus plays about 600 games (--games), half
against random teams and half against the teams that placed Top 8 or
better (--top), with the bot on both sides. The report ranks the teams by
Elo (Bradley-Terry; 0 is the average team) and shows each one's score
against the top teams, the mean Elo by tournament placement, and the mean
Elo of the teams each species is on. `--teams` rates only some teams
(still against the whole pool). Pastes that don't load are listed first,
with the reason. The ratings say how well the bot plays each team: teams
that need precise play rate low while the bot plays them badly.

## Play on Showdown

    python -m selfplay.showdown runs/ppo3/model.pt --team my_team.txt --user MyBot --password ... --challenge mikumiku37
    python -m selfplay.showdown runs/ppo3/model.pt --team my_team.txt --user MyBot --password ... --accept YourName --games 5

The bot logs in (a registered account needs its password, or set
SHOWDOWN_PASSWORD), uploads `--team` (a Showdown paste) and either
challenges the users given or accepts challenges from those listed
(`--accept` alone: anyone). The format defaults to
gen9championsvgc2026regmc; a best-of-3 challenge works too and counts as
one match of `--games`. It plays with the tree search (`--budget`, 2000
value evaluations a turn, a few seconds on a GPU) or the policy
(`--policy`), accepts Open Team Sheets (`--no-ots` to decline) and prints
every decision with its win estimate and top options. Logs go to
runs/showdown. Use it for private challenges with people who agreed to
play the bot.

It follows the battle from Showdown's messages and rebuilds the position in
the engine at each decision (tests/test_showdown.py checks it against
Showdown's own state). The opponent's unrevealed sets come from Open Team
Sheets, or else from usage stats; its unseen back two are the network's
guess.

To try it without an account, run a local server (in a pokemon-showdown
checkout: `node pokemon-showdown start --no-security`) and add
`--server ws://localhost:8000/showdown/websocket --local`.

## Regenerate data from Showdown

Showdown is the rules authority. Both scripts need a built checkout of
https://github.com/smogon/pokemon-showdown (`npm install && node build`):

    node selfplay/tools/showdown/export_dex.js   /path/to/pokemon-showdown
    node selfplay/tools/showdown/gen_fixtures.js /path/to/pokemon-showdown
    node selfplay/tools/showdown/protocol_fixtures.js /path/to/pokemon-showdown
    python selfplay/tools/gen_pool.py

`dex.json` records the Showdown commit it came from. Regenerate the fixtures
from the same commit, and commit the data, fixtures and any engine changes
they require together.
